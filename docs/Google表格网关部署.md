# Google 表格网关部署

本文件说明只读网关的部署；Python 接收与入库模块已实现（见 `app/leads/`）。

## 部署步骤

1. 打开持续接收线索的 Google 表格，选择“扩展程序 > Apps Script”。若已有旧项目脚本，保留旧脚本，新增一个 `.gs` 文件并不会隔离同名函数；应使用独立的 Apps Script 项目或确认旧网关不再使用后再替换。独立项目需要在项目设置的脚本属性中直接配置 `SPREADSHEET_ID` 和 `ACCESS_TOKEN`，无需运行依赖绑定表格的 `setup()`。
2. 将 `integrations/google_sheets/google_sheets_lead_gateway.gs` 的完整内容复制到新项目的脚本文件中，保存。
3. 对绑定到表格的新脚本，将 `INITIAL_ACCESS_TOKEN` 的占位值替换成密码管理器生成的至少 32 位随机字符串。保存，选择 `setup`，点击运行，按提示授权。此函数将令牌和当前表格 ID 写入脚本属性，不修改表格内容。也可以直接配置脚本属性而不在源码中填写令牌。
4. 选择“部署 > 新部署”，类型为“Web 应用”，执行身份选择自己，访问权限选择“任何人”。Python 不携带 Google 登录会话，网关通过请求正文中的令牌校验访问。组织账户若不允许该访问选项，需要另行解决组织的访问限制。
5. 点击部署，保存 Web 应用地址（末尾为 `/exec`）。同时保存目标工作表的 `gid` 和令牌，后续配置到 Python。`gid` 是浏览器打开该工作表时地址里的数字；不是工作表名字，也不是表格文件 ID。
6. 不需要创建表单提交触发器或定时触发器，轮询将由 Python 常驻服务负责。浏览器直接打开 `/exec` 发出的是 GET 请求，本脚本只接受 POST，不能据此判断接收是否正常。

部署后更改源码，需要在“部署 > 管理部署”中编辑对应部署并选择新版本，Web 应用才会使用新代码。脚本属性修改不需要重新部署。

## 请求约定

使用 POST JSON，令牌放在正文中，客户端需允许跟随 Apps Script 响应重定向。

打开接收时：

```json
{"token":"配置的令牌","gid":0,"action":"tail"}
```

响应中的 `next_row` 是当前最后一行加一。Python 将它保存到内存，开启前的全部行均跳过。行号是表格实际行号：第 1 行为表头，5 条数据对应第 2～6 行，下一次从第 7 行读。

开启期间：

```json
{"token":"配置的令牌","gid":0,"action":"read","start_row":7,"limit":100}
```

响应含 `headers`、`values`、`start_row`、`next_row`、`last_row` 和 `has_more`。每个 `values` 元素是一整行，空单元格保留位置；时间单元格由 JSON 序列化为 ISO 时间字符串。默认每批 100 行，上限 500 行。

Python 必须检查 `ok` 为 `true`，不能仅凭 HTTP 成功判断业务成功。错误响应为 `{"ok":false,"error":"错误原因"}`。只有新增行成功入库或确认主键重复后才能推进内存中的 `next_row`。网关本身不保存游标，也不依赖数据库内容。

## 运行边界

- 接收开关及可配置的轮询间隔由 Python 管理。网关无第二个业务开关。
- 每次重新打开接收，重新调用 `tail`。关闭期间的新增行不补入库。
- 来源表按行向末尾追加，不排序、删行或中间插入。新记录应整行写入；逐个填单元格可能导致 Python 提前读到不完整记录。
- `getLastRow()` 按有内容的末行确定起点；避免预先在未来数据行放置公式或其他内容。
- 网关只读取表格，不修改表格、不主动推送，也不写 MySQL。
- 本地已完成模拟检查；Google 授权、实际 Web 应用部署和端到端读取仍需在部署后验证。
